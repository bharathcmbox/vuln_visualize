Finding bugs got cheap.
Fixing them didn't.

AI cyber models now surface vulnerabilities far faster than anyone can remediate them — the "vulnpocalypse." This walks the pipeline from discovery to a deployed fix, shows where open-weight and frontier models each pull their weight, and marks the two steps where a tool, not a model, checks the work. Numbers are illustrative; sources are listed at the end.

What this shows

Turning an AI's bug report into a fix you can trust takes eight steps. The affordable way to run them: a cheap open-weight model drafts, a stronger frontier model reviews, and a tool checks the result — because a model can claim it fixed the bug, but only a sanitizer or a test can prove it. We didn't just draw this; we built and ran it:

Lab 1 · Web app

A model drafts a WAF-style virtual patch; real requests check it. Checked, passed.

Lab 2 · Native code

A libpng memory bug: the model writes a C fix, a sanitizer + test suite check it (plus an input-filter virtual patch). Passed.

Lab 3 · Real bugs

Real OSS-Fuzz vulnerabilities. On a live curl bug the draft-plus-review combo reproduced the maintainer's exact fix. Passed.

Where the findings go

One real-world snapshot: a month of AI-assisted discovery against ~1,000 open-source projects. Press play and watch the cohort shrink at each step. The gap between what is found and what is actually patched is the vulnpocalypse in one picture.

Only a small fraction of what is found ever gets fixed upstream — and "patched upstream" still isn't the same as installed by downstream users. The scarce resource is trusted remediation, not discovery.

Figures adapted from reporting on Anthropic's Project Glasswing / Claude Mythos (≈23,019 candidate findings → ≈6,202 high/critical → ≈530 disclosed → ≈75 patched upstream). Counts vary by source and snapshot; treat them as orders of magnitude.

Open-weight, frontier, or both

Open-weight models are cheap enough to run on every commit and keep your code in-house; frontier models lead on the long, high-judgment steps. The design that holds up: open models draft, a frontier model reviews, a tool certifies.

In both of our labs the cheap draft was plausible but shallow; the frontier review — a few cents, but hundreds of times the draft cost — is where the robustness actually came from. It caught bypasses and edge cases the open-weight draft missed. Spend frontier budget on review, not volume.

05

What to tell your team

  1. Discovery is no longer the hard part. Budget and staff for triage, patching, and disclosure.
  2. Let tools decide, not models. Every patch — human or AI — must pass a reproducible check (PoV replay, test suite, fuzz regression) before anyone trusts it.
  3. Open drafts, frontier reviews. Cheap models at volume; frontier budget on review and the hard cases.
  4. Virtual patches buy time, with an expiry date. A WAF rule or seccomp policy covers the gap until the real fix ships — track it so it doesn't become permanent, unaudited debt.
  5. A generic WAF blocks what it recognizes. That is exactly when teams over-trust it; a targeted, positive-model rule is what holds against novel variants.
